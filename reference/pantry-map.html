Pantry AI：責任與資料流

以目前程式碼為準。package.json：React 19.2.3 / Next.js 16.1.6。

層 檔案 責任
頁面協調 src/app/page.tsx 搜尋、勾選、dialog；組合子元件。
互動畫面 src/components/pantry/ 看板、卡片、表單、食譜對話框。
資料 Hook src/hooks/usePantry.ts Apollo query、mutation、refetch。
共用環境 src/components/providers/ Auth Context 與 Apollo Client/cache。
HTTP 入口 src/app/api/graphql/route.ts Next.js 接收請求，Apollo 處理 GraphQL；token 轉成 context。
業務規則 src/graphql/resolvers.ts 資料歸屬、庫存拆分合併、食材選擇。
資料庫 prisma/schema.prisma User、PantryItem、Recipe 模型；PostgreSQL 持久化。
AI 表單操作 src/app/actions/ai.ts Server Actions：自動分類與語音文字解析。

三條路徑

勾選：卡片 → 頁面 setSelectedItemIds → React 更新 UI

庫存操作：卡片／表單 → 頁面 → usePantry → HTTP
  → Next.js Route Handler / Apollo → resolver → Prisma → PostgreSQL

語音輸入：瀏覽器 SpeechRecognition → 文字 → Server Action
  → Gemini → 驗證回傳資料 → 填入表單 → 使用者送出後走庫存新增路徑

AI 食譜生成另走 GraphQL mutation → resolver → recipeGenerator → Gemini。生成與儲存是不同操作。

面試時保持精確

  • Hook 重用邏輯；這裡跨元件的伺服器資料由共用 Apollo cache 支持，不是「呼叫同一個 Hook 就自動共用所有 state」。
  • AuthProvider 的前端跳轉負責導覽體驗；GraphQL context 與 resolver 才檢查伺服器端存取權。demo_token 對應共用示範帳戶。
  • Server Action 的 server 執行位置不等於自動授權。目前 ai.ts 內沒有使用者身份檢查，不能宣稱所有後端入口都有相同驗證。
  • useCallback 穩定函式參照；不能僅憑使用它就宣稱子元件不會重新渲染。效能改善需量測。
  • 交易讓多筆寫入一起成功或失敗；目前部分讀取在交易外，不應宣稱已解決所有併發競爭。
